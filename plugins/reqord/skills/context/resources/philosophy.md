# 設計思想・5原則・ポジショニング

## Reqordが解決する4つの課題

| 課題 | 症状 |
|------|------|
| **要件の散在** | チャット・メモ・口頭に散らばり、同じ議論の繰り返しと矛盾する仕様が発生 |
| **コンテキストの消失** | 新メンバーやツールが背景を理解できない、設計判断が引き継がれない |
| **仕様の劣化（Spec Drift）** | 実装後に仕様がメンテナンスされず、「今も正しいのか」が分からない |
| **トレーサビリティの断絶** | 要件→仕様→コードの紐付け不明、変更影響が見えず予期しない破壊が発生 |

## 5つの設計原則

### 1. 構造化第一（Structure First）

要件をプレーンテキストではなく構造化データとして管理する。

- **YAML（メタデータ）+ Markdown（コンテンツ）** のハイブリッド形式
- YAML: ステータス、優先度、依存関係、バージョン履歴 — 機械処理に適した部分
- Markdown: 説明文、成功基準、背景 — 人間が読み書きしやすい部分
- **Zodスキーマ** で型安全性を確保し、CLIとWeb UIで同一のバリデーションを共有

### 2. ローカル完結（Local-First）

Gitリポジトリがシングルソースオブトゥルース（SSoT）。

- `.reqord/` ディレクトリにすべてのデータを格納
- SaaSやバックエンドサーバーは不要。オフラインで完全に動作
- `git clone` だけでプロジェクトの全コンテキストを再現可能

### 3. 機械可読性（Machine-Readable）

構造化データは人間だけでなくツールにとっても扱いやすい。

- YAML + Markdown のハイブリッド形式はプログラムによる解析・変換が容易
- CLIが構造を保証し、外部ツール連携に一貫したインターフェースを提供
- ProjectContextにより、プロジェクト全体の文脈を構造的に蓄積・参照可能
- 副次的に、AIエージェントが要件を正確に解釈するための基盤にもなる

### 4. Human-in-the-loop

自動化・ツール支援と人間の判断を適切に分離する。

- 要件の承認: PRベースのレビュー → CODEOWNERSによるApprove → マージで確定
- 仕様の承認: 同様のPRベースフロー
- ツール出力のレビュー: 自動生成された内容は必ず人間が確認してから適用
- **セキュリティ関連**（認証、決済、個人情報）は常に人間によるレビューが必須

### 5. Living Documentation

要件は使い捨てではなく「生きたドキュメント」。

- **バージョン管理**: 承認履歴（version, gitCommit, approvedBy, approvedAt）を追跡
- **ステータスライフサイクル**: draft → approved → implemented → deprecated
- **フィードバックループ**: 実装後のフィードバックが要件・仕様の更新につながる
- **影響分析**: 依存関係グラフで変更の波及範囲を把握

## What Reqord is NOT

| 誤解 | 実態 |
|------|------|
| **Spec-driven developmentツール** | コード生成はスコープ外。出力はGitHub Issue（実装タスク）であり、コードではない。spec-kitやkiroとは異なる |
| **Jira/Asanaの代替** | プロジェクト管理全般をカバーしない。要件管理という一つの領域に集中し、既存ツールと**併用**する設計 |
| **IDE拡張** | 特定のエディタに依存しない。CLI + Web UIの独立ツール |

**Reqordの本質**: 要件のライフサイクル管理 — 作成→承認→実装→フィードバック→更新のサイクルを回し続けること。

## Gitが基盤であることの意味

Reqordは意図的にGitを基盤に選んでいる:

- **変更履歴の完全な追跡**: `git log` で要件の変更経緯を辿れる
- **PRベースのレビュー・承認**: コードレビューと同じ習慣で要件をレビューできる
- **ブランチ戦略**: 要件の変更もfeatureブランチで安全に作業
- **既存CI/CDとの親和性**: GitHub Actionsで要件のバリデーションを自動化可能
- **アクセス制御**: リポジトリの権限管理をそのまま活用

コードと要件を同じリポジトリ・同じワークフローで管理することで、トレーサビリティが自然に実現される。
