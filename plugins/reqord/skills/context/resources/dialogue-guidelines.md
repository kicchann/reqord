# 対話設計ガイドライン

reqordスキルでAskUserQuestionを使った対話的ヒアリングを行う際の共通原則。

---

## 基本原則

### 1. 推定→確認パターン

ユーザーに「ゼロから書かせる」のではなく「AIが推定した結果をレビューさせる」。ユーザーの仕事は「作成」ではなく「確認と修正」。

### 2. 一石二鳥の質問

1つの質問から複数の情報を引き出す。「何を作りたいですか？」ではなく「これが完成したとき、誰がどう喜びますか？」と聞けば、ターゲットユーザー・価値・スコープが同時にわかる。

### 3. 具体例で引き出す

抽象的な質問は抽象的な答えを生む。「要件はありますか？」ではなく「今、最も困っている具体的な場面を教えてください」。

### 4. 制約から攻める

「何がしたいか」より「何をしたくないか」「何が使えないか」を聞くほうがスコープが早く定まる。

### 5. 沈黙は情報

「分からない」「まだ決まっていない」も重要な情報。無理に埋めさせず、未決定事項として記録する。

---

## 質問テンプレート

### トピック質問

```
<質問文。1〜2文で簡潔に。>（N/M）

（例: <回答例1>
      <回答例2>）
（スキップ → Enter）
```

### 確認質問

```
以下の内容で[操作名]します。修正があれば教えてください。

<構造化された内容>

（OKなら Enter / 修正点があれば記述してください）
```

---

## 言い回しガイド

トーンの指針: 同僚のシニアエンジニアが隣で聞いてくれている感覚。丁寧だが堅すぎず、技術者同士の会話として自然な表現。

| 場面 | 良い例 | 悪い例 |
|---|---|---|
| 質問の冒頭 | 「どんな要件を作りたいですか？」 | 「要件の詳細を入力してください。」 |
| 追加質問 | 「もう少し教えてください。」 | 「情報が不足しています。以下を入力してください。」 |
| スキップ許容 | 「わかる範囲で大丈夫です」 | 「任意入力です。未入力の場合はデフォルト値が適用されます。」 |
| 確認 | 「この内容で合っていますか？」 | 「以下の内容を確認し、承認してください。」 |
| 推定を使った場合 | 「回答から推定しました。違っていたら修正してください」 | 「デフォルト値を設定しました。」 |
| 完了 | 「作成しました。」 | 「処理が正常に完了しました。」 |

---

## 回答の具体度判定

ユーザーの回答レベルに応じて深掘りを判断する:

| 具体度 | 判定基準 | 対応 |
|--------|---------|------|
| HIGH | 動詞+目的語+理由/文脈、固有名詞・数値あり | 追加質問なし。構造化して確認 |
| MID | 動詞+目的語はあるが理由/ユーザー種別が不明 | 1問追加（誰が/なぜを補完） |
| LOW | 名詞のみ、キーワードレベル | 1問追加（何を/誰が/なぜを補完） |

深掘りは**最大1回**。それ以上の詳細が必要な場合は「あとから改善できます」と案内する。

---

## スキップ・中断への対応

| ユーザー入力 | 対応 |
|---|---|
| 「わからない」「あとで」「スキップ」 | AIが合理的に推定し、確認フェーズで明示。「あとから `/reqord:edit` で追加できます」 |
| 「キャンセル」「やめる」 | 即座に中止 |
| 空Enter | 確認フェーズでは「OK」として扱う。シード質問では再度促す |
| 大量のテキスト（コピペ等） | そのまま受け入れて構造化する |

## アンチパターン

### 一括質問爆弾

```
❌ 「以下を入力してください: 1. タイトル 2. 概要 3. 優先度 4. 複雑度 5. 成功基準...」
```

複数項目を一度に要求しない。核心の1問から始め、段階的に肉付けする。

### はい/いいえ地獄

```
❌ 「タイトルは〜でいいですか？」→「優先度はmediumでいいですか？」→ ...
```

1項目ずつ聞かない。まとめて確認フェーズで一括表示し、修正点だけ指摘してもらう。

### 専門用語の押しつけ

```
❌ 「EARSテンプレートとUser Storyのどちらを使用しますか？SMART基準に基づく成功基準を定義してください。」
```

reqordの内部概念をユーザーに理解させようとしない。AIが判断して適用する。

### 脱出不能な質問ループ

```
❌ Q: 成功基準を教えてください → A: わからない → Q: 必須です。入力してください
```

「わからない」には必ずスキップまたはAI推定で対応する。

### 過度な深掘り

```
❌ Q: 誰が使いますか？→ A: 管理者 → Q: 管理者の権限は？→ Q: 具体的にどの操作が？...
```

深掘りは最大1回。それ以上はSpecificationで詳細化する。

### 文脈なき選択肢

```
❌ 「優先度を選んでください: high / medium / low」
```

判断材料なしに選ばせない。AIが推定して理由とともに提示し、ユーザーは修正のみ行う。
