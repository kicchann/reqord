# CLIエラーハンドリング統一

## 概要

現在のCLIは各コマンドでエラー処理が個別実装されており、エラーメッセージの形式やプロセス終了コードが統一されていない。
共通のエラーハンドリング基盤を導入し、ユーザー体験を改善する。

## ユーザーストーリー

開発者として、CLIのエラーメッセージが一貫したフォーマットで表示されてほしい。
なぜなら、エラーの原因と対処法をすぐに理解したいから。

## 詳細要件

### 共通エラーパターン

| エラー種別 | メッセージ例 | 終了コード |
|-----------|-------------|-----------|
| 未初期化 | `Error: .reqord/ が見つかりません。先に reqord init を実行してください` | 1 |
| ファイル読み込み | `Error: req-000001.yaml の読み込みに失敗しました: ENOENT` | 1 |
| バリデーション | `Error: 不正な値です（詳細は req-000010 参照）` | 1 |
| 成功 | （通常出力） | 0 |

### 実装方針

- 共通エラークラスまたはユーティリティ関数を作成
- `.reqord/` 未初期化チェックを全コマンドの共通前処理に
- `process.exit()` の呼び出しを一元管理
- エラー出力は stderr に統一

## 技術的制約

- 既存コマンドの動作を破壊しないこと
- エラーメッセージは日本語で統一
- Node.js の exit code 規約に従う（0: 成功, 1: 一般エラー）

## エッジケース

- 権限エラー（ファイルの読み取り/書き込み不可）
- ディスク容量不足
- 不正なYAML形式のファイルが `.reqord/` に存在する場合
