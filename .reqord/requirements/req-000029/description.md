# プロジェクト設定ファイル（setting.yaml）によるワークフローカスタマイズ

## 概要

`.reqord/settings/setting.yaml` にプロジェクト固有の設定を定義し、承認フロー・ステータス遷移・バリデーションの挙動をカスタマイズ可能にする。個人プロジェクトから厳格な運用まで、プロジェクトの規模や方針に応じたワークフローを実現する。

## ユーザーストーリー

プロジェクト管理者として、設定ファイルでワークフローの挙動をカスタマイズしたい。
なぜなら、プロジェクトの規模や運用方針に応じて承認プロセスやバリデーションの厳格さを調整したいから。

## 詳細要件

### 1. Approval Prerequisites カスタマイズ

Specification/Requirement の承認前チェック項目を設定で制御する。

- **design.md チェック**: Specification 承認時の design.md 存在・内容チェックをスキップ可能にする（デフォルト: 有効）
- **description.md チェック**: Requirement 承認時に description.md の内容チェックを追加するか選択（デフォルト: 無効）
- **カスタムファイルチェック**: 承認時に必須とする追加ファイルを定義可能（例: `api-spec.yaml`）

### 2. ステータス遷移の PR 要否

ステータス変更時の PR 作成要否を設定で制御する。

- **draft → approved**: PR なしで直接変更可能にする（デフォルト: PR 必須）
- **approved → implemented**: PR を要求するオプション（デフォルト: PR なし）
- **toDraft（approved/implemented → draft）**: PR を省略可能にする（デフォルト: PR 必須）

### 3. ブランチ命名規則

PR 作成時のブランチプレフィックスをカスタマイズ可能にする。

- toApproved ブランチプレフィックス（デフォルト: 現状の固定値）
- toImplemented ブランチプレフィックス（デフォルト: 現状の固定値）
- toDraft ブランチプレフィックス（デフォルト: 現状の固定値）

### 4. フィードバックバリデーション

未解決フィードバック存在時の承認動作を設定で制御する。

- **ブロックモード**: 未解決フィードバックがある場合に承認をブロックするか（デフォルト: 警告のみ）
- **severity 閾値**: ブロック対象の severity レベル（例: critical 以上はブロック）

### 5. 自動 draft 戻し制御

approved/implemented 状態で内容変更した際の自動 draft 戻しの挙動を制御する。

- **always**: 内容変更時に常に draft に戻す（現在の動作、デフォルト）
- **major-only**: major バージョンバンプ時のみ draft に戻す（patch 変更ではステータス維持）
- **never**: 自動 draft 戻しを無効化

### 6. 不変条件の宣言

設定ファイル内に変更不可の項目を明示し、ユーザーに「ここは制御できない」ことを伝える。`z.literal(true)` で定義し、`false` 設定時はバリデーションエラーとする。

- **versioning**: バージョン履歴の記録（常に有効）
- **cyclicDependencyCheck**: 巡回参照チェック（常に有効）
- **statusTransitionRules**: ステータス遷移ルール（常に有効）
- **schemaValidation**: YAMLスキーマ検証（常に有効）

### 7. 整合性チェック

ステータス遷移時の整合性チェックの厳格さを設定で制御する。

- **spec 未実装警告**: `req implement` 時に紐づく spec が未実装の場合、警告をエラーに昇格するか（デフォルト: 警告）
- **依存先ステータスチェック**: 依存先のステータスに基づくチェックの厳格さ（デフォルト: 警告）

## ユースケース

1. 個人プロジェクト: PR なしで直接 approve、design.md チェック無効、フィードバックチェック無効、自動 draft 戻し=never
2. チーム開発（標準）: デフォルト設定のまま使用（自動 draft 戻し=always）
3. 厳格な運用: description.md チェック有効、フィードバック severity=critical でブロック、spec 未実装をエラー化、自動 draft 戻し=always

## 技術的制約

- 設定ファイルは `.reqord/settings/setting.yaml` に配置
- Zod スキーマで定義し、@reqord/shared に配置
- 設定ファイルが存在しない場合は全項目がデフォルト値で動作（後方互換性）
- 不明なキーは無視（将来のバージョンとの互換性）

## エッジケース

- setting.yaml が不正な YAML の場合はパースエラーを表示し、デフォルト値で動作
- 部分的に定義された設定はデフォルト値でマージ
- reqord init 時に setting.yaml のテンプレートを生成するか（将来検討）
