# Design Review Rules

## Architecture

### DO

- Mermaid図で可視化する
- レイヤー分離を明記する
- 依存方向を守る（Domain → Infrastructure は禁止）
- 各モジュールの責任範囲を明確にする

### DO NOT

- 単一責任原則に違反しない
- 循環依存を作らない
- God Class / God Module を作らない
- レイヤーをまたぐ直接参照をしない

## API Design

### DO

- RESTful原則を遵守する
- バージョニング戦略を明記する
- エラーハンドリングを統一する
- 入力バリデーションを定義する

### DO NOT

- 破壊的変更をしない（既存APIの変更）
- 認証なしエンドポイントを作らない
- 標準外HTTPステータスを使わない
- レスポンス形式を統一しない

## Database

### DO

- 正規化する（最低3NF）
- インデックス設計を行う
- マイグレーション戦略を明記する
- データ型を適切に選択する

### DO NOT

- NULL許容を多用しない
- varchar(MAX) を使わない
- 外部キー制約なしにしない
- マイグレーションなしでスキーマ変更しない
